Overview

Metacognitive Python
Learning Platform

A structured coding environment for teenagers — where thinking is the product, not the answer.

Students who use AI to write code learn nothing. Existing platforms teach tools, not judgment. This platform teaches the one skill AI cannot replace: knowing what you are doing and why.

Target User
Teenagers, 14–18, basic Python literacy, enrolled in school
Primary Buyer
Governments & schools — measurable metacognitive output
Core Loop
Frame → Attempt (gated AI) → Reflect → Follow-up
Differentiator
AI earns trust through student framing — not the other way around
Stage 1

Framing Phase

⊘ AI Locked
Q1 — Decomposition
"What are the distinct sub-problems this breaks into?"
Format: Free-text list — minimum 2 entries required
Each entry must name a sub-problem that could be worked on independently
Gate: vague single-line answers prompt → "Can you be more specific? What does [X] actually involve?"
Q2 — I/O Specification
"What goes in, what comes out, and what types?"
Format: Structured fields
— Input: name, type, description
— Output: name, type, description
— Edge cases: at least one must be named before proceeding
Q3 — Flowchart
"Build your approach as a node graph before writing any code."
Format: Interactive node-based UI
— Each node = a step, function, or decision point
— Each edge = data flow or control flow
— Each node is confidence-rated: 🟢 sure / 🟡 unsure / 🔴 guessing
— Saved as artefact, compared against final solution in Stage 3
AI unlocks only after all three gates are passed. Confidence ratings per node are stored as the student's upfront model.
Stage 2

The Attempt

✓ AI Available — Mediated

Student works in a Python editor. All AI interaction goes through the coaching agent. Three commands only.

IMPLEMENT <description>
Request menial, well-scoped execution. Dispatched directly to helper agent.
e.g. "IMPLEMENT binary search on a sorted list of integers"
e.g. "IMPLEMENT read lines from a .csv file into a list of dicts"
Rejected if core logic — "IMPLEMENT the main algorithm" → hard reject with rethink prompt
HELP <specific question>
Request coaching assistance. Coaching agent intercepts first — asks for hypothesis or what has been tried. Helper agent only invoked if the question is genuine.
e.g. "HELP why is my BFS not terminating" → coach: "Which node do you think it's looping on?"
Vague queries rejected → "What specifically don't you understand? What have you already tried?"
MODIFY <what changed and why>
Student explicitly flags that their earlier reasoning was wrong. Updates session record. Coach asks what triggered the change.
e.g. "MODIFY I thought I needed a dict but the right structure is a graph with an adjacency list"
e.g. "MODIFY my I/O spec was wrong — output should be a list not a single value"
Passive queries — "write this function", "solve this part for me" — are hard-rejected. Student is redirected to their Stage 1 flowchart and asked what that node was supposed to do.
Stage 3

Reflection

Three components. Mandatory after each solved problem.

Component A
Prompt Timeline

Visual flowchart of the entire session. Every interaction shown as a node.

Each node labeled by type:
— Framing input
— IMPLEMENT call
— HELP call
— MODIFY flag
— Coach pushback

Each node rated on: precision, menial vs. core, whether it led to progress.

Component B
AI Summary

Generated on request. Covers four dimensions:

— Subject: Python / algorithmic gaps identified

— Problem-solving: decomposition accuracy, approach correctness

— Metacognition: MODIFY frequency, confidence calibration

— AI usage: query precision, passive vs. active delegation

Component C
Flowchart Diff

Stage 1 flowchart shown side-by-side with the actual solution structure.

Student annotates each discrepancy:

— "This node was wrong because..."

— "I missed this step entirely..."

— "I underestimated complexity here..."

Diff is stored as part of the learning record.

The flowchart diff is the core learning artefact. Over time, the gap between upfront model and actual solution narrows — that convergence is the signal that real understanding is developing.
Stage 4

Follow-ups

Two targeted problems generated from the weakest dimension identified in Stage 3. Student can attempt now or defer to next session.

Trigger → Follow-up Type

Weak Decomposition
Same concept, decomposition must differ
Student's Stage 1 sub-problems were incorrect or incomplete. New problem forces a different breakdown of the same underlying concept.
Passive AI Usage
Same problem type, coaching agent is stricter
Student over-relied on IMPLEMENT or issued vague HELP calls. Identical problem category, but IMPLEMENT threshold raised — more must come from the student.
Miscalibrated Confidence
Variation where the obvious approach is a trap
Student was overconfident in nodes that turned out wrong. Follow-up is designed so the naive approach fails visibly — forces hypothesis revision mid-attempt.

What is being tested

Follow-ups are not more practice. They are transfer tests.

A student who improved their decomposition skill should demonstrate it on a different problem, not the same one repeated.

If performance improves only on seen problem types, the system flags this: the student may be pattern-matching the platform, not developing the underlying skill.

Transfer gap = improvement on training problems minus improvement on novel problems.
High transfer gap → alert teacher/dashboard.
Tracked Stats

Metrics & Dashboard

What is tracked across sessions — and what it actually means.

Calibration Curve
Confidence rated per flowchart node in Stage 1 vs. correctness of that node in the final solution. Plotted over sessions. A well-calibrated student has a tight correlation. Overconfidence and underconfidence are both visible.
Per session + longitudinal
Flowchart Accuracy
Structural similarity between Stage 1 upfront model and actual solution flow. Measured as node-match ratio. Improving score = student's mental model of problems is becoming more accurate before they write any code.
Per session + longitudinal
MODIFY Frequency
How often the student caught their own reasoning errors mid-attempt and issued a MODIFY command. High frequency early → honest self-monitoring. Decreasing over time → student is forming more accurate upfront models.
Per session + trend
Query Precision Score
Coaching agent rates each IMPLEMENT and HELP call on specificity and scope. Score tracks whether queries are getting more targeted over time. Rising score = student is learning to delegate intelligently rather than offload thinking.
Per session + trend
Coaching Pushbacks
Count of hard and soft rejections per session. Decreasing pushbacks = the habit of thinking-before-asking is forming. Used as a proxy for metacognitive discipline improving.
Per session + trend
Transfer Gap
Improvement on seen problem types vs. novel follow-up problems. Large gap = student pattern-matching the platform. Small gap = genuine skill transfer. Flags for teacher review if persistent.

The Pitch

Why Governments Buy This

What every other tool measures

Did the student get the right answer?
Did the code pass the test?
Did they complete the module?

These are output metrics that AI can fake entirely. A student who copies AI output passes every one of them.

What this tool measures

Does the student understand what they are doing?
Is their understanding real or illusory?
Are they improving at forming accurate mental models?
Can they transfer skills to problems they have not seen?

These are process metrics that cannot be faked without doing the actual learning.

The policy problem this solves

For governments

A generation of students is graduating with AI-assisted credentials that do not reflect genuine competence. This platform produces evidence of real understanding, not just correct outputs.

For teachers

The dashboard shows which students understand material and which ones only think they do — before the exam, not after. Calibration score and flowchart accuracy are early warning signals.

The core product value:
Measurable metacognitive output at scale.
Not grades. Not completion rates. Actual evidence of how a student reasons.
